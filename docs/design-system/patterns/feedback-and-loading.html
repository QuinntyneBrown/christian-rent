Pattern

Feedback and loading

Which kind of feedback answers which action, and how waiting looks.

WCAG 2.2 AA
  • Overview
  • When to use
  • Structure
  • States
  • Responsive behaviour
  • Accessibility
  • Content
  • Do and don’t
  • Sources

Overview

Every press gets an answer where the member is looking. Waiting is shown in the shape of what is coming.

When to use

SituationUse
A screen’s first loadSkeletons in the shape of the content, after 300 ms.
More of a list arrivingA spinner with words at the end of the list.
A form being sentThe pressed button goes busy.
A form sentA confirmation replaces it.
A request failedAn alert where it happened, with “Try again”.
An admin decidedA toast, because the item leaves the screen.

Structure

Loading more listings…

Skeleton, spinner with words, busy button.

States

Loading, loaded, more loading, more failed (the listings already shown stay), failed. A later search always replaces an earlier one; a slow early answer never overwrites it.

Responsive behaviour

Skeletons follow the same grid as the cards: one, two, three or four columns.

Accessibility

  • The loading container has aria-busy="true" and a hidden status names what is loading.
  • Results, confirmations and failures are announced through a live region.
  • Under reduced motion the shimmer and spinner stop; the words remain.

Content

  • “Loading more listings…”, “We couldn’t load more listings.”, “Try again”.
