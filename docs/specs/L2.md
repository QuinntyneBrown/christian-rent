# L2 - Detailed Requirements

Each acceptance test names the L2 requirements it covers in a comment at its head
(`// Acceptance Test`, `// Traces to: L2-001, L2-003`, `// Description: ...`).

## L2-001: Browse shows approved listings
**Traces to:** L1-001

Browse is the home screen. It shows approved listings, newest first, to anyone, signed in or not.
A listing for rent shows as a card with its first photo, title, price and area; a wanted listing
shows as a card with no photo.

**Acceptance Criteria:**
1. Given approved listings exist, when anyone opens christian.rent, then Browse shows them newest first without asking them to sign in.
2. Given a listing is waiting in the review queue or has been removed, when anyone opens Browse, then that listing is not shown.
3. Given a listing for rent with photos, when its card is shown, then the card shows the first photo, the title, the price and the area.
4. Given a wanted listing, when its card is shown, then the card shows no photo and is labelled "Wanted" in text.
5. Given a card on Browse, when a person selects it, then the Listing screen for that listing opens.
6. Given no approved listing exists, when anyone opens Browse, then an empty state is shown with the two buttons that lead to posting.
7. Given a listing for rent, when its card is shown, then the card also shows whether it is a space or a thing, and the name of the church of the member who posted it.
8. Given a wanted listing, when its card is shown, then the card shows "Wanted" with whether it is a space or a thing, the title, when it is needed, the name of the member who posted it and the name of their church, the area, and what the member will pay when they gave a price.
9. Given a card on Browse, when it is shown, then the distance of the listing from the person's area follows its area, for example "Langley · 3 km". Until a person's area can be set (an open decision, ADR 0012), the card shows the area alone, for example "Langley".
10. Given the list on Browse has loaded or changed, when it is shown, then the number of listings is announced to a screen reader, for example "7 listings".

---

## L2-002: Switch between Everything, For rent and Wanted
**Traces to:** L1-001

A switch on Browse limits the list to listings for rent, to wanted listings, or shows both.

**Acceptance Criteria:**
1. Given Browse is opened, when nothing has been chosen, then Everything is selected and both kinds of listing are shown.
2. Given Browse, when a person selects For rent, then only listings for rent are shown.
3. Given Browse, when a person selects Wanted, then only wanted listings are shown.
4. Given a search term is entered, when a person changes the switch, then the search term is kept and both apply together.
5. Given a choice on the switch, when the page is reloaded or its address is shared, then the same choice and search term are restored.
6. Given the switch, when it is shown, then each option shows the number of listings it holds for the current search term and the choice of Spaces or Things (L2-035); while the list is loading or has failed to load, no number is shown.

---

## L2-003: Search
**Traces to:** L1-001

The search bar finds approved listings by words in their title, note and area, without regard to
letter case or accents.

**Acceptance Criteria:**
1. Given approved listings titled "Parking space near church" and "Folding chairs", when a person searches "parking", then only the first is shown.
2. Given a listing whose note contains "gymnasium", when a person searches "GYMNASIUM", then that listing is shown.
3. Given a person is typing, when they pause for 300 ms, then the list updates without a page reload; an earlier search still in flight is cancelled and never replaces a later result.
4. Given a search term longer than 100 characters, when it is submitted, then only the first 100 characters are used.
5. Given a search term containing HTML or script, when the results are shown, then the term is rendered as text.
6. Given the search bar, when it is shown, then it has a field named "Search listings" that takes at most 100 characters and a "Search" button; selecting Search, or pressing Enter in the field, searches for the term as typed.
7. Given the search bar, when it is shown, then it shows the person's area and the distance the listings are within, in km, for example "Langley, BC · within 25 km"; it is text and not a control. Until a person's area can be set (an open decision, ADR 0012), it shows the launch area alone, "Langley, BC".

## L2-004: A search that finds nothing offers to post a request
**Traces to:** L1-001

**Acceptance Criteria:**
1. Given a search that matches no approved listing, when the results are shown, then a no-results state names the search term and offers to post a wanted listing for it.
2. Given the no-results state, when a person takes the offer, then Post opens set to "I need", with the search term as the title.
3. Given the no-results state, when it is shown, then it also offers "Clear search", which empties the search term and shows the list again.

---

## L2-005: Browse leads straight to posting
**Traces to:** L1-001

**Acceptance Criteria:**
1. Given Browse, when it is shown, then it has two buttons: "I have something to rent" and "I'm looking for something".
2. Given Browse, when a person selects "I have something to rent", then Post opens set to "I have".
3. Given Browse, when a person selects "I'm looking for something", then Post opens set to "I need".

---

## L2-006: Browse loads in pages
**Traces to:** L1-001

**Acceptance Criteria:**
1. Given more than 24 listings match, when Browse is opened, then the first 24 are shown and more load as the person reaches the end of the list.
2. Given the last page has loaded, when the person reaches the end, then no further request is made.
3. Given a page fails to load, when the failure happens, then the listings already shown stay, and a message with a "Try again" button is shown.
4. Given the next page is in flight, when the person is at the end of the list, then "Loading more listings" is shown after the last card and announced to a screen reader.

---

## L2-007: The Listing screen
**Traces to:** L1-002

**Acceptance Criteria:**
1. Given an approved listing for rent, when anyone opens it, then it shows its photos, title, whether it is a space or a thing, price, when it is available, area and note.
2. Given an approved wanted listing, when anyone opens it, then it shows its title, whether it is a space or a thing, what the person will pay if given, when it is needed, area and note, and no photo.
3. Given a listing with several photos, when a person moves through them, then each photo can be reached by touch and by keyboard, and each has a text alternative.
4. Given a listing that is not approved, has been removed or does not exist, when anyone but its own poster or an admin opens its address, then a "not found" state is shown and nothing about the listing is revealed.
5. Given a listing, when it is shown, then its area is a city or neighbourhood and never a street address.
6. Given a listing, when it is shown, then its distance from the person's area follows its area, in km, and it says how long ago it was posted, for example "Posted 2 days ago". Until a person's area can be set (an open decision, ADR 0012), the listing shows the area alone, for example "Langley".
7. Given a listing for rent with several photos, when it is shown, then one photo is shown large above a row of thumbnails; the large photo has a text alternative that describes the photo, each thumbnail is a control named by its position, for example "Photo 2 of 3", and the position of the photo shown is announced.
8. Given the Listing screen, when it is shown, then "All listings" leads back to Browse.
9. Given a listing for rent with one photo, when it is shown, then the photo is shown large with no thumbnails and no position; given one with no photo, then "No photo yet" is shown in the photo's place (ADR 0016).
10. Given a listing for rent, or a wanted listing that gave a price, when it is shown, then its price is shown beside the listing with the currency, for example "Rent for $45 CAD / hour" or "They'll pay Up to $120 CAD / day" (L2-022, criterion 9).

## L2-008: Who posted, and their church
**Traces to:** L1-002

**Acceptance Criteria:**
1. Given a listing, when it is shown, then it shows the name of the member who posted it and the name of their church.
2. Given the member is verified, when the listing is shown, then the member is marked "Verified" with text and an icon, not colour alone.
3. Given the church is verified, when the listing is shown, then the church is marked "Verified" in the same way, separately from the member.
4. Given the member or the church is not verified, when the listing is shown, then no verified mark is shown for it.
5. Given a listing, when it is shown to anyone, then the member's email address, phone number and street address are not shown and are not in the response.
6. Given a listing, when it is shown, then beside the member's name it shows their initials and the year they became a member, for example "Member since 2023".

## L2-009: Choose what is being posted
**Traces to:** L1-003

Post opens with one sentence, "I have / need a space / a thing to rent out". Both words of each
pair are shown and the chosen one is highlighted. "I have" makes a listing for rent; "I need"
makes a wanted listing.

**Acceptance Criteria:**
1. Given Post, when a member switches "have" to "need", then the listing becomes a wanted listing, the sentence reads accordingly, and the photos field is removed.
2. Given Post, when a member switches between "a space" and "a thing", then the listing's kind changes and the fields already filled in are kept.
3. Given Post, when the highlighted words are used with a keyboard or a screen reader, then each is a control with a name and a state that says which choice is selected.
4. Given a person who is not signed in, when they open Post, then they are taken to the sign-in page and returned to Post afterwards with their choices kept (L2-037, criterion 5); given a person signed in who is not a member, then they are asked to become a member, and Post keeps their choices whatever they answer.
5. Given "have" is chosen, when Post is shown, then the sentence ends "to rent out", the title field asks "What is it?", the price field is "Price" and the submit button reads "Publish listing"; given "need" is chosen, then the sentence ends "to rent", the title field asks "What do you need?", the price field is "Your budget" and the submit button reads "Post request".
6. Given Post is opened with no choice between a space and a thing, when it is shown, then "a thing" is chosen.

## L2-010: The fields of a listing
**Traces to:** L1-003

A listing has a title, a price, when, an area, photos (for rent only) and a note.

**Acceptance Criteria:**
1. Given Post, when a member submits a title shorter than 3 or longer than 80 characters, then the listing is not posted and the title field says why.
2. Given a listing for rent, when a member submits no price, a negative price or a price above 100,000, then the listing is not posted and the price field says why; a price of 0 is accepted and shown as "Free".
3. Given a listing for rent, when a member sets the price, then they choose what it is per: hour, day, week or month.
4. Given a wanted listing, when a member leaves the price empty, then the listing is accepted and shows no price.
5. Given Post, when a member fills in "when", then they give either free text of up to 80 characters (for example "Weekday evenings") or a start and end date; an end date before the start date is refused.
6. Given Post, when a member submits no area, then the listing is not posted and the area field says why.
7. Given Post, when a member writes a note longer than 1,000 characters, then the listing is not posted and the note field says why; the note is optional.
8. Given invalid fields, when the member submits, then every invalid field is marked at once, a summary above the fields lists them, focus moves to the summary, each entry in the summary moves focus to its field, and nothing the member typed is lost.
9. Given a request sent straight to the backend with invalid fields, when it is received, then the backend refuses it with the same rules.
10. Given Post, when "when" is shown, then it is a text field; "Give dates instead" replaces it with a start and an end date, and "Describe it in words instead" brings the text field back.
11. Given Post, when its fields are shown, then the note and the price of a wanted listing are labelled "Optional"; the title, the price of a listing for rent, "when" and the area carry no such label and are required.
12. Given Post, when a member submits no "when", then the listing is not posted and the field says why.
13. Given Post, when the area field is shown, then it is labelled "Where" and says that it takes a city or neighbourhood in Canada and never a street address.
14. Given a wanted listing, when a member gives a price, then they choose what it is per as for a listing for rent, and it is shown as "Up to" and the price, for example "Up to $120 / day".
15. Given the title, "when" or the note, when a member types, then the field takes no more than its limit, and the note shows how many of its 1,000 characters are used.

## L2-011: Live preview
**Traces to:** L1-003

**Acceptance Criteria:**
1. Given Post, when a member changes any field, then the preview card updates to show the listing as it will appear on Browse.
2. Given a wanted listing, when the preview is shown, then it is a card with no photo.
3. Given an empty field, when the preview is shown, then the card shows a placeholder in its place and never the word "undefined" or an empty price.
4. Given Post, when the preview is shown, then the card carries the name of the member's church and, for a wanted listing, the member's name, as it will on Browse; it shows the area without a distance.
5. Given a listing for rent with no photo yet, when the preview is shown, then the card shows the placeholder image, named "No photo yet".
6. Given a person who is not a member yet, when the preview is shown, then it shows "Your church" in place of the church and, for a wanted listing, "Your name" in place of the member's name (ADR 0019).

## L2-012: Posting and confirmation
**Traces to:** L1-003

**Acceptance Criteria:**
1. Given valid fields, when a member submits, then the listing is saved as waiting for review, it enters the review queue, and a confirmation is shown.
2. Given a listing waiting for review, when the confirmation is shown, then it says truthfully that the listing will appear once it has been reviewed, and does not say it is already public.
3. Given the listing is approved, when anyone opens Browse, then the listing is shown.
4. Given a member selects the submit button twice, when both requests arrive, then one listing is created.
5. Given the request fails, when the failure happens, then the form keeps everything the member entered, including photos already added, and offers "Try again".
6. Given a member has posted 10 listings in 24 hours, when they post another, then it is refused with a message saying when they can post again.
7. Given Post, when it is shown, then it says before the member submits that prices are in CAD and that an admin reviews every listing before it appears on Browse.
8. Given the listing is being sent, when the member waits, then the submit button shows that it is busy and cannot be pressed again, and the fields cannot be changed.
9. Given the confirmation, when it is shown, then it reads "Sent for review", shows the card as it will appear on Browse, and offers "Back to browsing" and "Post another"; it offers no way to edit the listing.
10. Given a post is refused because of the limit of 10 in 24 hours, when the refusal is shown, then everything the member entered is kept and the submit button is off.
11. Given a member has entered a draft, when they reload Post or leave it and come back in the same tab, then the draft is still there; it is cleared once the listing is sent or the member chooses "Post another" (ADR 0019).

## L2-013: Add photos to a listing for rent
**Traces to:** L1-004

**Acceptance Criteria:**
1. Given a listing for rent, when a member adds photos, then up to 6 are accepted, each shows a thumbnail, and the first is the one shown on the card.
2. Given photos have been added, when a member removes or reorders them, then the preview card follows. Reordering waits for its mock, an open decision; until it is drawn, the photos stay in the order they were added (ADR 0021).
3. Given 6 photos are added, when the photos field is shown, then the Add button is off and a message says to remove one to add another; a seventh photo sent straight to the backend is refused.
4. Given a listing for rent with no photo, when it is posted, then it is accepted and its card shows a placeholder image.
5. Given a photo is uploading, when the member leaves Post, then the upload is cancelled and the photo is not kept.
6. Given a listing for rent, when the photos field is shown, then it shows how many of the 6 photos are added, for example "1 of 6", marks the first photo "On the card", gives each photo a Remove button named by its position, and states the limits: up to 6, JPEG, PNG or WebP, 10 MB or less each.
7. Given a photo is uploading, when the photos field is shown, then its thumbnail shows that it is uploading and has a button that cancels the upload.
8. Given a photo cannot be uploaded because christian.rent cannot be reached, when the photos field is shown, then a message names the file and says to try adding it again, and the photos already added stay (ADR 0021).
9. Given photos have been added to a listing for rent, when a member switches to "need" and back to "have", then the photos are still there; a wanted listing is posted with none (ADR 0021).

## L2-014: Photos are checked before they are stored
**Traces to:** L1-004

**Acceptance Criteria:**
1. Given a file that is not a JPEG, PNG or WebP image by its content, when it is uploaded, then it is refused whatever its file name or declared type.
2. Given an image larger than 10 MB, or smaller than 400 × 300 px either way round, or larger than 8,000 px on either side, when it is uploaded, then it is refused with a message naming the limit (ADR 0021).
3. Given an accepted photo, when it is stored, then its location data and other embedded metadata are removed.
4. Given an accepted photo, when it is shown, then it is served from file storage at a size fitted to where it appears, and never from the database.
5. Given a photo belonging to a listing that is not approved, when anyone but its poster or an admin requests it, then it is not served.
6. Given a photo is refused, when the refusal is shown on Post, then the message names the file and the limits, and the photos already added stay.
7. Given a photo was uploaded and no posted listing names it, when 24 hours have passed and the clean-up runs, then the photo and its files are deleted (ADR 0021).
8. Given a member's photo that no posted listing names, when anyone but that member requests it, deletes it or posts a listing with it, then it is refused and nothing about it is revealed; the member may delete it (ADR 0021).

## L2-015: Send a message about a listing
**Traces to:** L1-005

The Listing screen has a message box that sends a message to the person who posted.

**Acceptance Criteria:**
1. Given a member on an approved listing, when they write a message of 1 to 1,000 characters and send it, then the message is delivered to the person who posted and a confirmation replaces the message box.
2. Given a listing for rent, when the message box is shown, then it has start and end dates; given a wanted listing, then it has none.
3. Given dates are entered, when the end date is before the start date, the start date is in the past or only one of the two is given, then the message is not sent and the field says why. Dates are optional: a message about a listing for rent with neither date is sent (ADR 0022).
4. Given an empty message or one over 1,000 characters, when the member sends it, then it is not sent and the field says why.
5. Given a person who is not signed in, when they try to send a message, then they are taken to the sign-in page and returned to the listing with their message and dates kept; given a person signed in who is not a member, then they are asked to become a member, and their message and dates are kept.
6. Given a member's own listing, when they open it, then the message box is not offered: in its place the panel shows the price and "This is your listing.", and a message sent to it straight to the backend is refused.
7. Given sending fails, when the failure happens, then the message text and dates are kept and "Try again" is offered. Given the listing was taken down in the meantime, then the screen shows that the listing is not there, and the text and dates are still kept.
8. Given the message box, when it is shown, then its heading and its button name the person who posted, as "Message" and the name for a listing for rent and "Offer to help" and the name for a wanted listing; it shows the price, with "CAD", as "Rent for" or "They'll pay"; it shows how many of the 1,000 characters are used; and it says that no payment happens here and the two people agree the details together.
9. Given dates are entered, when they are valid, then a line under them reads them in words with how many days they span, for example "Sat, Jun 13, 2026 · one day" or "Jun 13 to 15, 2026 · 3 days".
10. Given an invalid message or invalid dates, when the member sends, then every invalid field is marked at once, a summary lists them, focus moves to the summary, each entry in the summary moves focus to its field, and nothing the member typed is lost.
11. Given the message is being sent, when the member waits, then the button shows that it is busy and the message and dates cannot be changed.
12. Given the confirmation, when it is shown, then it reads "Sent to" and the name of the person who posted, says that they can read the message and reply and that nothing is booked or paid here, quotes the message and its dates back, and offers a way back to Browse; it does not say where the reply will arrive.
13. Given a wanted listing that gave no price, when the message box is shown, then it has no price and is otherwise the same.
14. Given a message was typed and not sent, when the member reloads the Listing screen or returns to it in the same tab, then the text and dates are still there; once it is sent they are cleared (ADR 0022).

## L2-016: A message is private to the two people
**Traces to:** L1-005

**Acceptance Criteria:**
1. Given a message, when it is delivered, then only the member who sent it and the member who posted the listing can read it.
2. Given a message is delivered, when the person who posted reads it, then they see the sender's name, church and verified marks, the listing it is about, the dates if any, and a way to reply. This criterion waits for the Messages inbox, which is not designed; until then a message is stored for the two people and no endpoint returns it (ADR 0022).
3. Given a message, when it is sent, then neither person's email address or phone number is revealed to the other unless they write it themselves.
4. Given a member has sent 20 messages in an hour, when they send another, then it is refused with a message saying when they can send again: when the twentieth most recent is an hour old.
5. Given a listing that has been removed, when a member tries to send a message about it, then it is refused.
6. Given a message is refused because of the limit of 20 in an hour, when the refusal is shown, then the message text and dates are kept and the send button is off until sending reopens.
7. Given a member has left, when their personal data is deleted (L2-028, criterion 2), then the text of every message they sent is cleared, and the messages about their listings are deleted with those listings.

---

## L2-017: Becoming a member
**Traces to:** L1-006

**Acceptance Criteria:**
1. Given a person who is not a member, when they join, then they give their name and their church, and declare that they are a Christian; without all three they do not become a member.
2. Given a person joins, when they name their church, then they pick an existing church or enter a new one with its name and city.
3. Given a new member, when they join, then they enter the review queue as a new member and are not verified.
4. Given a member who is not yet verified, when they post or send a message, then they may, and their name is shown without a verified mark.
5. Given a person who is not a member, when they browse, search or read a listing, then they may; when they post, message or report, then the backend refuses until they are a member.
6. Given a name longer than 60 characters, a church name longer than 100 or a church's city longer than 80, when it is submitted, then it is refused with the reason (ADR 0018).
7. Given the join dialog, when it is shown, then it says that browsing is open to anyone, that posting, messaging and reporting need a member, and that what the person has filled in is kept; "Not now" leaves without joining.
8. Given the join dialog, when the church field is shown, then it lists the existing churches, each with its city, and "My church isn't listed"; choosing that shows fields for the church's name and city, and says that an admin confirms a new church before it is shown as verified.
9. Given the join dialog, when it is shown, then the declaration is a checkbox that reads "I am a Christian".
10. Given the join dialog is sent with no name, no church or no declaration, when it is refused, then each missing one is marked and says why, and what was entered is kept.
11. Given joining is in flight, when the person waits, then the button shows that it is busy and the fields cannot be changed; given joining fails, then what was entered is kept and "Try again" is offered.
12. Given a person who is not a member, when they send a message or a report, then the same join dialog is shown as when they open Post, its title naming what they were doing: "Become a member to post", "Become a member to send a message" or "Become a member to report" (ADR 0018).
13. Given the join dialog, when the list of churches cannot be loaded, then the church field says so and offers "Try again", and "My church isn't listed" can still be chosen (ADR 0018).
14. Given a person who is already a member, when they join again, then nothing new is created and they stay the same member.
15. Given a new church whose name and city match an existing church apart from capitals, accents and spacing, when a person joins with it, then the existing church is used and no second one is created (ADR 0018).

## L2-018: Verified members and churches
**Traces to:** L1-006

**Acceptance Criteria:**
1. Given a new member in the review queue, when an admin approves them, then the member is verified and the mark appears on their listings.
2. Given a church entered by a member, when an admin confirms it, then the church is verified and the mark appears on the listings of all its members.
3. Given a member is verified and their church is not, when their listing is shown, then only the member is marked.
4. Given an admin removes a member, when the removal is made, then from their next request the member's session no longer works and they can no longer sign in, post or message, and their listings are no longer public (L2-040, criterion 4).
5. Given anyone other than an admin, when they try to set a verified mark, then the backend refuses.
6. Given a new member whose church is not verified, when an admin approves the member, then the member is verified and the church is not.

## L2-019: The review queue
**Traces to:** L1-007

**Acceptance Criteria:**
1. Given an admin, when they open Admin, then the review queue lists new listings, reports and new members, oldest first, each labelled with its kind.
2. Given an admin selects an item, when it opens, then a detail panel shows everything needed to decide: for a listing, all its fields and photos and who posted it; for a report, the listing and the reason; for a new member, their name and church.
3. Given the queue is empty, when an admin opens Admin, then "All caught up" is shown.
4. Given more than 50 items wait, when an admin opens Admin, then they load in pages.
5. Given a person who is not signed in to Admin as an admin, when they open Admin or call its endpoints, then the backend refuses, no queue data is returned, and the review queue's code is not loaded; a person not signed in to Admin is shown Admin's sign-in page (L2-038, criteria 2 and 3).
6. Given the review queue, when it is shown, then its heading says how many items wait and that the oldest is first; each item shows the title of the listing or the name of the member, who posted or which church, how long it has waited, and its kind as "New", "Reported" or "New member".
7. Given a new listing, when its detail is shown, then it shows whether the listing is for rent or wanted and for a space or a thing, the verified marks of the member and the church, since when the poster has been a member, and when it was posted.
8. Given a report, when its detail is shown, then it shows the reason, the note if one was written, how long ago it was reported, and since when the listing has been public; it says that the report is from a member and does not name them; "View on site" opens the listing.
9. Given a new member, when their detail is shown, then it shows when they joined, their declaration, their church with its city, whether the church is new to christian.rent and who entered it, how many listings they have and whether those are public, and how many messages they have sent; it offers no control for the church.
10. Given more items wait than are loaded, when the queue is shown, then its heading says how many are shown, for example "63 waiting · oldest first · showing 50".
11. Given a person signed in to Admin who is not an admin, when they open Admin, then the screen says that the page is for admins, names who is signed in, and offers "Sign out" and a way to christian.rent.
12. Given new items arrive while an admin is reviewing, when Admin next looks, which it does every 60 s while the page is visible, then a notification says how many arrived and what they are, for example "A new listing and a report arrived while you were reviewing.", and offers "Show them", which reads the queue again from its oldest item; once dismissed it returns only when more have arrived (ADR 0027).
13. Given the queue opens from 768 px, when it has loaded, then its first item is selected and that item's detail is shown; below 768 px no item can be selected and no detail is asked for. Admin's own photos of an item are read through Admin's endpoints, with the Admin session.
14. Given how long an item has waited, when it is shown, then it reads "just now" under a minute, then whole minutes ("12 min"), hours ("3 hr") and days ("1 day", "2 days"), rounded down.
15. Given a listing for rent with several photos, when its detail is shown, then every photo is shown, the first large and the others under it, in the member's order; given a listing for rent with no photo, then it says that the listing has no photo; a wanted listing shows its title on a wanted block instead.
16. Given a new member's church, when their detail is shown, then its status reads "Verified" when an admin has confirmed it; otherwise "New to christian.rent, entered by this member", "New to christian.rent, entered by" and that member's name, or "Not verified" when who entered it is not recorded.
17.
