Theming

Three tiers of tokens, a light theme that is the design, and a dark theme built from the same roles.

WCAG 2.2 AA
  • Overview
  • How themes apply
  • How dark was built
  • Using tokens.json
  • Usage

Overview

tokens/tokens.css is the single source of truth. Primitives hold raw values, semantic tokens give them a role, and components read roles. A theme overrides semantic tokens and nothing else.

How themes apply

  • Light is :root. It is the design: plain white.
  • Dark applies with data-theme="dark" on <html>, or when the system prefers dark and the page has not asked for light.
  • color-scheme is set in each, so native date fields and scrollbars follow.
  • More contrast (prefers-contrast: more) strengthens hairlines and secondary text; forced colours hand edges and focus to the system.

How dark was built

Dark is not light inverted. The page is deep navy and surfaces get lighter as they rise. The plain primary action flips to a light fill with ink text. Orange and blue fills keep their hue, because they are the meaning; orange and blue text gets lighter. Status backgrounds become deep tints with light text.

Using tokens.json

tokens/tokens.json is the same set in the Design Tokens Community Group format, generated from the CSS. Use it to generate constants for another platform. Never edit it by hand: change tokens.css and regenerate.

Usage

  • Never write a colour, a size from the scales, or a duration in a component.
  • A new theme is a new [data-theme] block of semantic overrides, followed by the contrast check.
  • In the app, global styles hold only these foundations; each component has its own encapsulated stylesheet that reads them by role.
