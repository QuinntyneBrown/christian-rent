Pattern

Empty and error states

What to show when there is nothing to show, and how to word it.

WCAG 2.2 AA
  • Overview
  • When to use
  • Structure
  • States
  • Responsive behaviour
  • Accessibility
  • Content
  • Do and don’t
  • Sources

Overview

An empty or failed screen is still a screen: it keeps its header and controls, says what happened and offers one way forward.

When to use

SituationTitleWay forward
No listing exists yet“Nothing is posted near Langley yet.”The two buttons that lead to posting.
A search found nothing“Nobody has ‘hot air balloon’ yet.”“Ask for ‘hot air balloon’”, which opens Post set to “need” with the term as the title.
A request failed“We couldn’t load the listings.”“Try again”.
A listing is gone, not approved or never existed“This listing isn’t here.”“Browse all listings”. Nothing about the listing is revealed.
No such address“We can’t find that page.”“Go to Browse”.
Not an admin“This page is for admins.”“Go to Browse”. No queue data is sent.
The queue is empty“All caught up”None needed.

Structure

Nobody has “hot air balloon” yet.

Post a request and the people near Langley who can help will see it.

Responsive behaviour

The message is centred in the content column and never wider than 28 rem. Its buttons wrap.

Accessibility

  • The title is a real heading.
  • A failure is also announced.
  • The search term is rendered as text.
  • No technical detail is ever shown.

Content

Formula: what happened, in the member’s words; one sentence on what to do; one button that does it.
