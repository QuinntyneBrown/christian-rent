Text field

One line of text in a bordered box: a name, a church, a city.

WCAG 2.2 AAStatus: stable

Overview

Use the bordered text field inside dialogs and for short secondary answers. On Post, where the fields are the screen, use the line field. Always wrap it in a form field so it has a label.

Anatomy

  1. LabelAbove the box, always visible.
  2. Value16 px, so a phone does not zoom in.
  3. Box48 px tall, --radius-md, a 1 px edge in --color-border-strong.

Text

Responsive behaviour

A field fills its column. Two fields share a row from 576 px inside a dialog and stack under it.

Theming

Text field reads only semantic tokens, so it follows the theme with no rule of its own. The colour tokens it reads are --color-fg-default, --color-bg-surface, --color-border-strong, --color-fg-subtle, --color-fg-muted, --color-focus-ring and others listed under Tokens. To restyle it, change those tokens; never write a colour in the component.

Accessibility

Role and pattern

A native <input> with a <label>.

Keyboard

KeyAction
Tab Moves in and out.
Enter Submits the form it is in.

Focus

The shared focus ring: a 2 px outline in --color-focus-ring, offset 2 px, never removed.

Labelling

A visible label, never a placeholder alone. An error is tied with aria-describedby and the field carries aria-invalid="true". maxlength matches the limit in the requirement (60 for a name, 100 for a church).

Contrast

Text in the box
Placeholder
Edge
Invalid edge

Motion

Colour and position changes take --duration-fast or --duration-base with --ease-standard. With reduced motion the tokens drop to 0.01 ms, so nothing moves.

Touch

Every interactive part is at least 44 × 44 px (--target-min). Nothing depends on hover.

Content

  • The label is a noun: “Your name”, “Church name”, “City”.
  • A placeholder is an example, never an instruction, and never the only label.
